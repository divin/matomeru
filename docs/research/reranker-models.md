# Cross-encoder reranker models for local relevance scoring

**Checked:** 2026-11-11
**Purpose:** Pick a cheap, local reranker to score all ~110 Reddit threads against the interest profile *before* LLM summarization, so only the top ~25–30 threads are sent to the (slow, sequential) LLM. Constraints: home server with Intel Arc B60 (24 GB VRAM) running a llama.cpp-style OpenAI-compatible server (LM Studio or llama-server, GGUF), CPU available for small models, content mostly English with some German (r/de, r/Finanzen).

All benchmark numbers below are **publisher-reported** (model cards / vendor blogs), not independent reruns. BEIR and MTEB-R numbers from different papers use different first-stage retrievers and dataset subsets, so treat cross-source comparisons as indicative, not exact. I could not scrape the live MTEB leaderboard (Gradio space, not machine-readable via curl) — spot-check current standings at the [MTEB leaderboard](https://huggingface.co/spaces/mteb/leaderboard) before committing.

### Ranking for this use case (EN+DE, tiny cost, local, GGUF-friendly)

1. **BAAI/bge-reranker-v2-m3** — the only top-quality candidate that llama.cpp's rerank endpoint was explicitly built and tested for (see §2), Apache-2.0, multilingual incl. German, 8k context, tiny at Q8 (~600 MB). Quality is mid-pack in 2026 terms but ample for "is this Reddit thread interesting to me" filtering.
2. **Qwen/Qwen3-Reranker-0.6B** — clearly better reranking quality than bge-v2-m3 (+8.8 MTEB-R, +8.0 MMTEB-R per Qwen's own runs) at the same 0.6B scale, Apache-2.0, German covered, instruction-aware. Costs more per pair (causal-LLM forward pass) and the GGUF path has a footgun (see §2).
3. **mixedbread-ai/mxbai-rerank-base-v2** — best quality-per-cost of the encoder-side options if you run in-process Python (sentence-transformers supports it directly); no verified llama.cpp serving path.
4. **Alibaba-NLP/gte-multilingual-reranker-base** — 306M, 70+ languages, would rank higher, but it ships a custom `trust_remote_code` architecture ([card](https://huggingface.co/Alibaba-NLP/gte-multilingual-reranker-base)), which makes ONNX/GGUF conversion and long-term maintenance worse.
5. Everything English-only (MiniLM-L6, gte-reranker-modernbert-base, granite reranker, zerank-2) — disqualified by r/de + r/Finanzen content.
6. Jina v2/v3/v3.5 — excellent quality (v3.5 claims BEIR 63.20) but NC-licensed and listwise/custom interfaces; not worth the coupling for a personal tool unless quality of German filtering proves insufficient.

## 2. Integration paths on this stack

### llama.cpp / llama-server: native rerank support — yes

- llama-server has a rerank endpoint with aliases `/rerank`, `/v1/rerank`, `/v1/reranking`, accepting both TEI format (`query` + `texts`) and Jina format (`query` + `documents`). It requires a reranker model plus `--rerank`/`--reranking` (or `--embedding --pooling rank`). ([tools/server/README.md](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md))
- The feature landed in [PR #9510](https://github.com/ggml-org/llama.cpp/pull/9510) and the server README names [bge-reranker-v2-m3](https://huggingface.co/BAAI/bge-reranker-v2-m3) as the reference model. ([server README](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md))
- Model format: GGUF converted with `convert_hf_to_gguf.py`; the converter registers `XLMRobertaForSequenceClassification` and explicitly handles bge-reranker-v2-m3 tensor names ([conversion/bert.py](https://github.com/ggml-org/llama.cpp/blob/master/conversion/bert.py)). Ready-made GGUFs: [gpustack/bge-reranker-v2-m3-GGUF](https://huggingface.co/gpustack/bge-reranker-v2-m3-GGUF) (most-downloaded community conversion).
- Caveat from the README: bidirectional-encoder rerankers like bge-v2-m3 must fit the whole query+document inside `--ubatch-size` (default is small; raise it for long posts). Causal-decoder rerankers (e.g. Qwen3-VL-Reranker) have no such limit. ([server README](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md))
- **ModernBERT-based rerankers (gte-reranker-modernbert-base, granite) are NOT supported**: there is no modernbert architecture in llama.cpp's arch table or converter as of this check ([src/llama-arch.cpp](https://github.com/ggml-org/llama.cpp/blob/master/src/llama-arch.cpp), [conversion/](https://github.com/ggml-org/llama.cpp/tree/master/conversion)). Community "GGUF" uploads of these exist but I found no evidence they run under `--pooling rank`.
- Qwen3-Reranker GGUFs work with `--reranking --pooling rank` **if converted correctly** — many community GGUFs produce garbage scores (`4.5e-23`) because reranker-specific tensors are missing ([llama.cpp issue #16407](https://github.com/ggml-org/llama.cpp/issues/16407)). Verified-working conversions: [Voodisss/Qwen3-Reranker-0.6B-GGUF-llama_cpp](https://huggingface.co/Voodisss/Qwen3-Reranker-0.6B-GGUF-llama_cpp) (Q4_K_M within ±1% NDCG@10 of F16 on MTEB AskUbuntuDupQuestions, served via llama-server `/v1/rerank`; community benchmark, not peer-reviewed). The official-looking [ggml-org/Qwen3-Reranker-0.6B-Q8_0-GGUF](https://huggingface.co/ggml-org/Qwen3-Reranker-0.6B-Q8_0-GGUF) is an automated `gguf-my-repo` conversion with no reranker-specific handling stated — treat with caution.

### LM Studio: no reranker support

- LM Studio still has no reranker model support or `/v1/rerank` endpoint. The feature request [lmstudio-bug-tracker#470](https://github.com/lmstudio-ai/lmstudio-bug-tracker/issues/470) has been open since Feb 2025 with "+1" comments through Oct 2026 and no maintainer response; a sibling request exists for the `lms` CLI ([lms#167](https://github.com/lmstudio-ai/lms/issues/167)). Users in that thread report embedding models load via manual architecture override, but the rerank scoring head/route is absent.
- **Workaround:** run a second, tiny llama-server process on the same machine (e.g. port 9091) next to the existing server at 192.168.178.64:9090. A 568M reranker needs <2 GB VRAM at Q8 (or run it CPU-only with `--n-gpu-layers 0`), so it coexists fine with the LLM on the Arc B60. The XLM-RoBERTa-family reranker is a standalone classifier — it has nothing to do with the chat model, and llama.cpp's `--reranking` mode exists precisely for serving it separately ([server README](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)).

### In-process Python (CPU)

- [sentence-transformers `CrossEncoder`](https://sbert.net/docs/cross_encoder/usage/usage.html) scores `[(query, doc), ...]` pairs directly with one line and supports ONNX/OpenVINO backends; the canonical retrieve-and-rerank recipe is [SBERT Retrieve & Re-rank](https://sbert.net/examples/applications/retrieve_rerank/README.html). Qwen3-Reranker-0.6B ships a first-class CrossEncoder interface, including a custom-instruction prompt ([card](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B)); there is also a community sequence-classification conversion, [tomaarsen/Qwen3-Reranker-0.6B-seq-cls](https://huggingface.co/tomaarsen/Qwen3-Reranker-0.6B-seq-cls), for standard classifier tooling.
- bge-reranker-v2-m3 via [FlagEmbedding](https://github.com/FlagOpen/FlagEmbedding) `FlagReranker` (with `use_fp16=True` for speed) or via CrossEncoder ([card](https://huggingface.co/BAAI/bge-reranker-v2-m3)).
- Qwen3-Reranker's model card *recommends* flash-attention-2 "for better acceleration and memory saving" but the unaccelerated path is the default usage and runs on CPU; FA2 is an optimization, not a requirement ([card](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B)). The 4B card is the same.
- ONNX/OpenVINO speedup: pre-built exports exist ([onnx-community/bge-reranker-v2-m3-ONNX](https://huggingface.co/onnx-community/bge-reranker-v2-m3-ONNX); the MiniLM card ships OpenVINO int8 weights, [card](https://huggingface.co/cross-encoder/ms-marco-MiniLM-L6-v2)); sentence-transformers supports ONNX backends ([docs](https://sbert.net/docs/cross_encoder/usage/usage.html)).
- [Text Embeddings Inference (TEI)](https://github.com/huggingface/text-embeddings-inference) is a third serving option (Docker, x86): it exposes a `/rerank` route and the gte-reranker card shows bge-class rerankers deployed through it ([example](https://huggingface.co/Alibaba-NLP/gte-reranker-modernbert-base)); the bge-v2-m3 card is tagged `text-embeddings-inference` ([card](https://huggingface.co/BAAI/bge-reranker-v2-m3)). Probably overkill given llama-server already covers this.
- **CPU latency:** I found **no primary benchmark** for per-pair CPU latency of these rerankers; treat the following as unverified estimates: MiniLM-L6 (22.6M params) ~1–5 ms/pair on a modern desktop CPU (its card only benchmarks 1800 docs/s on a V100, [card](https://huggingface.co/cross-encoder/ms-marco-MiniLM-L6-v2)); bge-reranker-v2-m3 (568M XLM-R) on the order of 100–500 ms/pair at fp32 CPU, several× faster with ONNX int8; Qwen3-Reranker-0.6B similar or slower (causal-LLM forward pass). For 110 pairs/run all of these finish in seconds-to-minutes on CPU and effectively instantly on the Arc GPU. The only hard number I can cite is mxbai's A100 measurement of 3.05 s per query (reranking NFCorpus candidates) for bge-v2-m3 vs 0.67 s for mxbai-rerank-base-v2 ([v2 blog](https://www.mixedbread.ai/blog/mxbai-rerank-v2)) — GPU, and the per-query candidate count is unspecified there.

## 3. Practical guidance

- **Sequence limits:** bge-reranker-v2-m3 handles 8,192-token pairs (config `max_position_embeddings: 8194`, [config.json](https://huggingface.co/BAAI/bge-reranker-v2-m3/blob/main/config.json)); gte-modernbert/granite/gte-multilingual 8,192 ([cards](https://huggingface.co/Alibaba-NLP/gte-reranker-modernbert-base)); Qwen3-Reranker 32k ([card](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B)); mxbai v2 "8K (32k-compatible)" ([blog](https://www.mixedbread.ai/blog/mxbai-rerank-v2)); jina-v2 only 1,024 with sliding windows beyond ([card](https://huggingface.co/jinaai/jina-reranker-v2-base-multilingual)); MiniLM-L6 and mxbai-v1 only **512** ([card](https://huggingface.co/cross-encoder/ms-marco-MiniLM-L6-v2)).
- **Reddit posts fit.** The plan scores `title + body` (not comments). Typical Reddit self-posts are a few hundred to ~2,000 tokens, so even a 1k-token model mostly fits, and 8k models never truncate. If you later include top comments, stay with ≥8k models. Under llama-server, remember `--ubatch-size` must exceed the longest pair ([server README](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)).
- **"Title + body" as the document is standard practice** — rerankers are plain `query, document` text pairs; the canonical SBERT recipe concatenates whatever text represents the document ([Retrieve & Re-rank](https://sbert.net/examples/applications/retrieve_rerank/README.html)). Join as `f"{title}\n\n{body}"`.
- **Long queries:** an interest-profile *section* as the query works (it's just a string), but cross-encoders are trained on short queries; a multi-paragraph profile can compress score separation. Judgment call (no primary source): keep the query to the core topical keywords of the section, or score once per interest sub-topic and take the max per thread.
- **Top-k strategy:** score all 110, sort by raw score descending, take top 25–30 — this is exactly the rerank-then-LLM pattern ([Retrieve & Re-rank](https://sbert.net/examples/applications/retrieve_rerank/README.html)); llama-server's `/v1/rerank` returns all scores sorted, with optional `top_n` ([server README](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)). Since every thread is scored against the *same* query in one request, a fixed top-N is robust; an absolute sigmoid threshold on top can catch days where nothing is interesting, but don't assume cross-request score calibration.
- **Instructions:** Qwen3-Reranker is instruction-aware (custom task instruction improves results 1–5%, recommended written in English) ([card](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B)) — an easy fit for "rank how interesting this is to me". bge-v2-m3 takes no instruction.

## 4. State of the art check (anything clearly beating bge-reranker-v2-m3 at ≤0.6B for EN+DE?)

Yes, as of Nov 2026 the small-multilingual crown has moved on from bge-v2-m3 (March 2024):

- **Qwen3-Reranker-0.6B** (June 2025, Apache-2.0): MTEB-R 65.80 vs bge-v2-m3 57.03, multilingual 66.36 vs 58.36 — Qwen's own runs, +8–9 points ([blog](https://qwenlm.github.io/blog/qwen3-embedding/)).
- **jina-reranker-v3.5** (July 2026, CC-BY-NC): self-reported BEIR 63.20, above Qwen3-Reranker-4B (62.28) at 0.6B ([card](https://huggingface.co/jinaai/jina-reranker-v3.5)).
- **mxbai-rerank-base-v2** (2025, Apache-2.0): BEIR 55.57, multilingual 28.56 ([blog](https://www.mixedbread.ai/blog/mxbai-rerank-v2)).
- Qwen3-VL-Reranker-2B/8B (Jan 2026) extend the line multimodally ([HF](https://huggingface.co/Qwen/Qwen3-VL-Reranker-2B)); llama-server even documents serving them ([server README](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)).

The catch: the 2025+ leaders are all **causal-LLM rerankers** (Qwen3/Qwen2.5 backbones), not classic encoders — heavier per pair and, for llama.cpp serving, dependent on correctly-converted GGUFs ([#16407](https://github.com/ggml-org/llama.cpp/issues/16407)). bge-reranker-v2-m3 remains the quality floor that everything else is measured against and the only one with a zero-friction path on this exact stack.

## Design decision

- **Primary: BAAI/bge-reranker-v2-m3**, served as a llama-server sidecar on the Arc B60 machine: `llama-server -m bge-reranker-v2-m3-Q8_0.gguf --reranking --pooling rank --port 9091 --ubatch-size 4096` (Q8 from [gpustack](https://huggingface.co/gpustack/bge-reranker-v2-m3-GGUF); flags per [server README](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)). Matomeru calls `POST http://192.168.178.64:9091/v1/rerank` once per run with query = interest-profile section and 110 `documents` = `title\n\nbody`, takes the top 25–30 by returned score, and sends only those to the LLM. Rationale: native endpoint support, EN+DE, Apache-2.0, trivially cheap — 110 pairs ≈ seconds on the Arc GPU or a few minutes worst-case on CPU (estimate; no primary benchmark available).
- **Fallback: Qwen/Qwen3-Reranker-0.6B** if bge-v2-m3's German filtering proves too coarse. Two serving options: (a) llama-server with a verified-working GGUF ([Voodisss/Qwen3-Reranker-0.6B-GGUF-llama_cpp](https://huggingface.co/Voodisss/Qwen3-Reranker-0.6B-GGUF-llama_cpp) — validated against llama.cpp `/v1/rerank`); (b) in-process `CrossEncoder("Qwen/Qwen3-Reranker-0.6B")` on CPU, which works without flash-attention ([card](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B)). Use its instruction prompt to express "personal relevance" (English instruction, per the card).
- **Do not use** cross-encoder/ms-marco-MiniLM-L6-v2 despite its convenience — English-only and 512-token cap ([card](https://huggingface.co/cross-encoder/ms-marco-MiniLM-L6-v2)) — nor gte-reranker-modernbert-base / granite reranker (English-only, [cards](https://huggingface.co/Alibaba-NLP/gte-reranker-modernbert-base)) on German subreddits.
- **Expected per-run cost:** reranking 110 pairs is a one-time, sub-minute cost (GPU) per run; the LLM summarization stage drops from ~110 × 3.3 min ≈ 6 h to ~25–30 × 3.3 min ≈ 1.4–1.7 h, i.e. roughly a 4× reduction in the dominant cost. If quality holds, consider cutting to top 20 for ~1.1 h.
- Before committing, spot-check the [MTEB leaderboard](https://huggingface.co/spaces/mteb/leaderboard) reranking board (I could not machine-read it) and, ideally, eyeball-score 20–30 threads both models rank top-30 — published BEIR/MTEB deltas do not directly measure "matches my personal interest profile" behavior.

## Gaps / uncertainty

- CPU per-pair latencies for MiniLM-class vs 568M-class rerankers are estimates; no primary benchmark was found. Measure on the actual server before choosing the CPU path (a 110-pair run is a 2-minute experiment).
- Cross-publisher BEIR/MTEB comparisons use different retrievers and dataset subsets; the only apples-to-apples table found is Qwen's blog (same candidate sets) and jina's v3.5 card.
- Live MTEB leaderboard values for the "Reranking" category could not be fetched programmatically (Gradio space).
- Whether a naive `gguf-my-repo` Qwen3-Reranker GGUF (e.g. ggml-org's own upload) works under `--reranking` is unverified; the safe option is the Voodisss conversion validated in issue #16407's thread.
